# dtp — プロンプト作成の補助

日本語のシーン記述からプロンプトを組み立て、語彙や表現の効果を実測する。

`dtq`（キューのワーカー）とは実行時に一切繋がらない。共有するのは
`config.local.sh` のモデル設定だけ。出力を `dtq` の job JSON にできるので、
繋ぎたくなったら `queue/` に置くだけで済む。

---

## 1. なぜ翻訳しないのか

このモデルのテキストエンコーダは Qwen3-VL 4B で、**日本語がそのまま通る**。
実測では英語に劣らず、日本の情景ではむしろ日本語のほうが文脈が濃い。
写真用語も `逆光` は `backlit` と、`中望遠レンズ・浅い被写界深度` は
`85mm medium telephoto lens, shallow depth of field` と同等に機能する。

一方で**何を書くかは支配的に効く**。記述量を増やす効果は、言語を変える効果に匹敵した。

したがってこの道具は翻訳も語彙辞書も持たない。**書き忘れを潰すことだけをする。**

測定の詳細は [findings.md](findings.md) D 章。

## 2. シーン記述

`キー: 値` の1行1スロット。`#` はコメント、空行は無視。全角コロンも読む。

```
場所:   夕方の喫茶店の窓際
主題:   20代の女性が席に座っている
服装:   ベージュのざっくりしたニットを着ている
光:     窓からの逆光で、髪の輪郭が明るく光っている
雰囲気: 少し憂鬱そうな、物思いにふける表情
カメラ: 中望遠レンズ、浅い被写界深度で撮影され、背景の店内は大きくぼけている
媒体:   フィルム写真

seed:   424242
width:  832
height: 1216
```

### スロット

出力は必ずこの順に並ぶ。実測で良好だったプロンプト構造に合わせてある。

| スロット | 必須 | 欠けたときの実測 |
|---|---|---|
| `場所` | | |
| `主題` | **必須** | |
| `動作` | | |
| `服装` | 推奨 | 無いと全身の量産型ストック写真になる（10.5倍） |
| `光` | 推奨 | 無いと平坦な環境光のまま（11.9倍） |
| `雰囲気` | 推奨 | 構図が寄らない（10.5倍） |
| `カメラ` | 推奨 | 被写界深度が効かない（11.9倍） |
| `媒体` | 推奨 | フィルム調などの質感が出ない（11.9倍） |
| `補足` | | 最後に付ける自由記述 |

倍率は「その群を足したときの平均画素差がノイズ下限の何倍か」。

各スロットは**完結した文**で書く。文末の句点は無ければ補う。
語順の保証だけをして、文そのものは組み替えない。

### 生成パラメータ

`seed` `steps` `width` `height` `count` `negative`。値の範囲は dtq と同じ。
`width` と `height` は両方セットで指定する。

### 弾かれるもの

| | |
|---|---|
| 未知のキー | タイプミスを黙って無視しない |
| キーの重複 | |
| SD1.5 系の呪文 | `masterpiece` `best quality` など。効かないか逆効果 |
| 重み記法 | `(word:1.2)` `{word}` `[word]`。このモデルは解釈しない |
| 2000文字超 | |
| タグ列 | 短い断片が5個以上並んでいたら警告（エラーにはしない） |

## 3. 使い方

```bash
dtp compose <scene>     # プロンプトを組み立てて出力
dtp lint    <scene>     # 検査だけ
dtp job     <scene>     # dtq の job JSON を出力
dtp diff    <a> <b>     # 生成済み2枚の画素差を測る

dtp ab <scene> --slot <名> --variants <値> <値> [...]
```

キューに流す:

```bash
dtp job scene.txt > ~/Library/Mobile\ Documents/com~apple~CloudDocs/DrawThingsQueue/queue/x.json
```

## 4. A/B テスト

`ab` は1スロットだけを振り、**同一シードで**生成して画素差を並べる。

```bash
dtp ab scene.txt --slot 光 --variants "窓からの逆光" "柔らかい順光" "夕方の斜光"
```

### 画素差の読み方

同一プロンプト・同一シードでも画像はビット一致しない。GPU の浮動小数点の
畳み込み順序が実行ごとに変わるため、画素の 85% が相違する。ただし平均絶対差は
**4.85/255** で見た目は区別できない。

この 4.85 を下限として、変化がその何倍かで判定する。

| ノイズ比 | 判定 |
|---|---|
| 〜1.5倍 | 変化なし（実行ごとのゆらぎと区別できない） |
| 〜4倍 | わずかな変化 |
| 〜10倍 | 明確な変化 |
| 10倍〜 | 大きな変化 |

**数値は「変わったか」しか言わない。「良くなったか」は目で見て決める。**
そのための材料として、同一シードで並べることに意味がある。

未検証の語彙が効くかどうかは、この手順で自分で確かめられる。

---

## 5. スコープ外

- **翻訳** — 日本語が通るので不要（§1）
- **語彙辞書** — 同上。効いた表現は findings.md に書き足していく
- **dtq への組み込み** — いまは繋がない。`job` の出力を `queue/` に置けば足りる
- **良し悪しの自動判定** — 画素差は変化量であって品質ではない
